# IPXE 分析功能使用指南

## 📋 功能概述

IPXE 分析功能提供完整的 IPXE 伺服器監控和日誌管理，包括：
- ✅ 多台 IPXE 伺服器管理
- ✅ 自動收集 Docker 容器日誌（透過 SSH）
- ✅ 即時日誌查看與篩選
- ✅ 統計圖表與趨勢分析
- ✅ 每 10 分鐘自動更新

---

## 🚀 快速開始

### 1. 訪問 IPXE 分析頁面

在左側選單點擊 **「IPXE 分析」**：

```
側邊欄 → IPXE 分析
```

### 2. 添加 IPXE 伺服器

首先需要添加要監控的 IPXE 伺服器：

1. 點擊左側選單 **「IPXE 管理」**
2. 點擊右上角 **「新增 Server」** 按鈕
3. 填寫伺服器資訊：
   - **名稱**: IPXE Server 50
   - **IP 地址**: 10.250.50.2
   - **描述**: IPXE 伺服器 (10.250.50.x 網段)
   - **SSH 使用者名稱**: rvt
   - **SSH 密碼**: 1.a
   - **SSH 端口**: 22
   - **MAC 容器名稱**: ipxe_mac-flask
   - **BOOT 容器名稱**: ipxe
4. 點擊 **「確定」** 儲存

### 3. 手動同步日誌

添加伺服器後，首次需要手動同步日誌：

1. 在 IPXE 管理頁面，找到剛添加的伺服器
2. 點擊 **「同步日誌」** 按鈕
3. 等待同步完成（約 1-2 秒）
4. 查看統計卡片更新的數字

## 📊 IPXE 分析頁面

### 切換伺服器

頁面右上角的下拉選單可以切換要查看的伺服器：

- **◈ 所有 Server（彙總）**: 顯示所有伺服器的彙總資料
- **🟢 10.250.50.2 (IPXE Server 50)**: 顯示特定伺服器的資料
  - 🟢 在線
  - 🔴 離線
  - 🔄 同步中

### Tab 1: 概覽

顯示 IPXE 日誌的整體統計：

#### 統計卡片
- **總日誌數**: 最近 7 天的總日誌量
- **MAC 日誌**: MAC 管理操作數量
- **BOOT 日誌**: IPXE 開機請求數量
- **Set 操作**: 設置 MAC BOOT 旗標的次數
- **Get 操作**: 查詢 MAC 配置的次數

#### 每日趨勢圖
- 顯示最近 7 天的日誌趨勢
- 藍色：MAC 日誌
- 綠色：BOOT 日誌
- 可以看出日誌的高峰時段

#### 啟動檔案統計
- 顯示 Top 10 最常被請求的 IPXE 檔案
- 例如：boot.ipxe, wimboot, LiteTouchPE_x64.wim 等

### Tab 2: 日誌查看

即時查看和搜尋 IPXE 日誌：

#### 篩選功能
- **日誌類型**: MAC / BOOT / 全部
- **時間範圍**: 最近 1 天 / 3 天 / 7 天
- **搜尋**: 依客戶端 IP、MAC 位址搜尋
- **刷新**: 手動重新載入日誌

#### 日誌表格
顯示欄位：
- **時間**: 日誌發生時間
- **類型**: MAC 或 BOOT
- **客戶端 IP**: 發起請求的 IP 地址
- **操作**: set_mac, get_mac, boot.ipxe, wim_file 等
- **狀態碼**: HTTP 狀態碼（200 = 成功）
- **詳情**: 查看完整日誌內容

#### 詳細資訊
點擊 **「詳情」** 按鈕可查看：
- 完整 HTTP 請求 URL
- MAC 位址（若為 MAC 日誌）
- BOOT 旗標（若為 Set 操作）
- 請求檔案名稱（若為 BOOT 日誌）
- User Agent（客戶端類型）
- 傳輸位元組數
- 原始日誌

### Tab 3: 統計分析

深入的統計圖表和趨勢分析：

#### 每小時日誌趨勢
- 顯示最近 24 小時的日誌分佈
- 可以看出高峰和低谷時段

#### 伺服器狀態總覽
- 顯示所有伺服器的運行狀態
- 包含：總日誌數、MAC/BOOT 分類、最後同步時間

#### 大檔案傳輸統計
- WIM 檔案下載次數
- 總傳輸量
- 平均檔案大小

## ⚙️ 自動化任務

### 自動日誌收集

系統會每 10 分鐘自動收集日誌（需設置 Cron）：

```bash
# 設置自動化
./scripts/setup_ipxe_cron.sh
```

設置後會：
- ✅ 每 10 分鐘從所有在線伺服器收集日誌
- ✅ 每天凌晨 2 點清理 7 天前的舊日誌

### 查看自動化日誌

```bash
# 查看收集日誌輸出
tail -f /var/log/ipxe_collect.log

# 查看清理日誌輸出
tail -f /var/log/ipxe_cleanup.log
```

## 📝 使用場景

### 場景 1: 監控 IPXE 開機活動

**目的**: 查看哪些客戶端正在使用 IPXE 開機

1. 進入 **「IPXE 分析」** → **「日誌查看」**
2. 篩選條件設為 **「BOOT」**
3. 查看最近的開機請求
4. 點擊 **「詳情」** 查看客戶端 IP 和請求的檔案

### 場景 2: 追蹤特定 MAC 位址

**目的**: 查看某台機器的 MAC 配置變更歷史

1. 進入 **「IPXE 分析」** → **「日誌查看」**
2. 篩選條件設為 **「MAC」**
3. 在搜尋框輸入 MAC 位址（例如：`60:cf:84:dc:b7:b5`）
4. 查看該 MAC 的所有 Set 和 Get 操作記錄

### 場景 3: 分析 WIM 檔案下載

**目的**: 統計 Windows PE 映像檔的下載情況

1. 進入 **「IPXE 分析」** → **「統計分析」**
2. 查看 **「大檔案傳輸統計」** 區塊
3. 可看到：
   - 下載次數
   - 總傳輸量（GB）
   - 平均檔案大小

### 場景 4: 監控伺服器健康狀況

**目的**: 確認所有 IPXE 伺服器正常運作

1. 進入 **「IPXE 管理」**
2. 查看所有伺服器卡片的狀態
3. 若有 🔴 離線狀態，點擊 **「同步日誌」** 嘗試重連
4. 檢查 SSH 連接是否正常

## 🔍 日誌類型說明

### MAC 日誌（ipxe_mac-flask 容器）

記錄 MAC 位址管理操作：

- **set_mac**: 設置 MAC 的 BOOT 旗標
  - `BOOT=1`: 啟用 PXE 網路開機
  - `BOOT=0`: 停用 PXE 網路開機
  
- **get_mac**: 查詢 MAC 的配置資訊
  - 通常由 IPXE 客戶端在開機時查詢

**範例日誌**:
```
10.252.170.188 - SET MAC 60:CF:84:DC:B7:B5 BOOT=1 (ansible-httpget)
10.250.54.11 - GET MAC 60:cf:84:dc:b7:b5 (iPXE/1.21.1+)
```

### BOOT 日誌（ipxe 容器）

記錄 IPXE HTTP 服務的檔案請求：

- **boot.ipxe**: IPXE 開機腳本
- **wimboot**: Windows 啟動載入器
- **BCD**: Windows 啟動配置數據
- **boot.sdi**: 系統部署映像
- **wim_file**: Windows PE 映像檔（通常很大，275 MB+）

**範例日誌**:
```
10.250.53.25 - GET /boot.ipxe (200, 116 bytes)
10.250.53.25 - GET /wimboot (200, 62,440 bytes)
10.250.53.25 - GET /LiteTouchPE_x64.wim (200, 576,926,332 bytes)
```

## ⚡ 性能提示

### 日誌數量限制

- 預設保留 **7 天** 日誌
- 單次收集 **1000 條** 日誌（可調整）
- 每 10 分鐘自動收集

### 調整保留天數

```bash
# 保留 14 天
docker exec nt-django python manage.py cleanup_ipxe_logs --days 14

# 保留 3 天（節省空間）
docker exec nt-django python manage.py cleanup_ipxe_logs --days 3
```

### 調整收集頻率

編輯 Crontab：
```bash
crontab -e

# 改為每 5 分鐘收集
*/5 * * * * docker exec nt-django python manage.py collect_ipxe_logs --limit 1000
```

## 🛠️ 故障排查

### 問題 1: 日誌不會自動更新

**原因**: Cron 任務未設置

**解決方法**:
```bash
./scripts/setup_ipxe_cron.sh
crontab -l  # 確認任務已添加
```

### 問題 2: 無法同步日誌

**可能原因**:
- SSH 連接失敗
- Docker 容器不存在
- 密碼錯誤

**檢查步驟**:
1. 確認伺服器 IP 可以 ping 通
2. 測試 SSH 連接：`ssh rvt@10.250.50.2`
3. 檢查 Docker 容器：`sudo docker ps`
4. 查看 Django 錯誤日誌：`tail -f logs/django_error.log`

### 問題 3: 前端顯示空白

**原因**: API 請求失敗

**解決方法**:
1. 打開瀏覽器開發者工具（F12）
2. 查看 Console 錯誤訊息
3. 檢查 Network tab 的 API 請求狀態
4. 確認後端 Django 服務正在運行：`docker compose ps`

### 問題 4: 統計數字不準確

**原因**: 資料未同步

**解決方法**:
1. 進入 IPXE 管理頁面
2. 點擊 **「同步日誌」** 更新資料
3. 或等待下一次自動收集（每 10 分鐘）

## 📌 注意事項

1. **SSH 密碼安全**: 密碼儲存在資料庫中，生產環境建議使用 SSH Key
2. **網路限制**: 確保 Django 容器可以訪問 IPXE 伺服器的 SSH 端口（22）
3. **容器名稱**: 不同伺服器的容器名稱可能不同，請確認正確
4. **時區**: 所有時間顯示使用伺服器時區（Asia/Taipei）
5. **效能**: 大量日誌可能影響查詢速度，建議定期清理舊資料
